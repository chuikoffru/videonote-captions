# Video to Circle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation was authorized on 2026-11-13.

**Goal:** Принимать обычное видео и возвращать кружочек Telegram без субтитров либо с существующими пословными субтитрами.

**Architecture:** Расширить текущий Go-бот: меню под исходником, короткоживущее состояние выбора и общий media pipeline. Нормализовать выбранный фрагмент в квадрат до распознавания; простой режим пропускает ASR. Переиспользовать действующие субтитры и кредитный резерв; отдельный дневной лимит простой конвертации хранить в PostgreSQL.

**Tech Stack:** Go, github.com/go-telegram/bot, FFmpeg/ffprobe, ASS/libass, PostgreSQL/GORM, существующий Whisper.

**Spec:** [Исследование и проект решения](../specs/2026-11-13-video-to-circle-design.md).

**Status:** Пользователь согласовал реализацию по плану: оба режима, простая конвертация бесплатно до 5 в день, субтитры по текущим условиям. Деплой и приёмка реальными Telegram-клиентами выполняются отдельно.

**Execution:** Код задач 1–5 реализован и проверен. Чек-лист ниже сохранён как исходный план; фактические проверки и оставшаяся ручная приёмка перечислены в [отчёте](../validation/2026-11-13-video-to-circle.md).

## Global Constraints

- Рабочий код находится в `/Users/konstantin/Developer/videonote-captions`; пути ниже указаны относительно него. Текущая папка чата содержит только документы.
- Вход: не более `20 * 1024 * 1024` байт и 600 секунд. Выход: 384×384, до 60 секунд, H.264/yuv420p, AAC при наличии звука, `+faststart`, не более 10 MiB.
- Простая конвертация: предлагаемый отдельный лимит 5 успешных результатов в день, Europe/Moscow. Субтитры: действующие настройки месячного лимита и цены, без второй платы за конвертацию.
- Два одновременных задания на весь бот; таймаут обработки 180 секунд. Ожидающее меню живёт 30 минут, после перезапуска недействительно.
- Только личные чаты для нового сценария. Длинное видео обрезается только после подтверждения. Для каждого исходника выбирается один режим; для второго результата можно прислать файл снова.
- Ни тарифные предложения, ни новый код не считать согласованными только из-за наличия этого плана.

## Review Focus

- iPhone MOV с поворотом, HEVC или HDR: правильная ориентация и цвета либо понятный отказ до списания — задача 1.
- Видео без звука и ролик с музыкой без речи: простой кружок работает, бесполезные субтитры не оплачиваются — задачи 1, 4.
- Два быстрых нажатия, несколько исходников подряд и старое меню после перезапуска: не перепутать файл и не списать дважды — задача 3.
- Ошибка скачивания/FFmpeg/Telegram и отмена: освободить слот, вернуть резерв и удалить временные файлы — задачи 2, 4.
- Бесплатная конвертация не должна попасть в платные метрики или изменить существующие monthly credits — задачи 2, 5.

## Задача 1. Проверяемая конвертация произвольного видео

**Интерфейсы нового пакета video:**

```go
type MediaInfo struct {
    DurationSeconds float64
    Width, Height int
    HasAudio bool
    IsHDR bool
}
type CircleOptions struct { DurationSeconds float64 }
func Probe(ctx context.Context, inputPath string) (MediaInfo, error)
func ConvertToCircle(ctx context.Context, inputPath, outputPath string, opts CircleOptions) error
```

`DurationSeconds` — разрешённая длина начала исходника, не произвольный seek. Отдельная функция валидации использует metadata; output проверяется повторным Probe.

- [ ] Добавить тесты на ffprobe fixtures: portrait/landscape/square, display rotation 90°, HEVC MOV, файл без аудио, битый файл, нечисловую/нулевую длительность и исходник >600 секунд. Проверять геометрию по содержимому кадра, а не только размер результата.
- [ ] Запустить `go test ./internal/video -run 'TestProbe|TestConvert' -v`, подтвердить отсутствие реализации.
- [ ] Реализовать Probe и ConvertToCircle через `exec.CommandContext`, JSON ffprobe, явный выбор видеопотока, центральный квадрат после нормализации ориентации, AAC для необязательного аудио. ffmpeg не должен читать stdin. Весь результат пишется в каталог задания.
- [ ] Проверить реальные выходы: квадрат 384×384, SAR=1, правильная ориентация, длительность ≤60, файл ≤10 MiB, читаемый H.264 и AAC. Silent input не получает искусственную аудиодорожку. Для HDR добавить проверенный SDR tone mapping либо явную неподдерживаемую ошибку до резерва; зафиксировать выбранное поведение тестом.
- [ ] Прогнать профильные тесты в Docker-окружении с FFmpeg; пропущенный media-тест не засчитывать как проверенную конвертацию. Зафиксировать отдельным коммитом.

## Задача 3. Приём видео и меню выбора

**Интерфейсы:** `(*Handler).VideoHandler(ctx context.Context, b *bot.Bot, update *models.Update)` и `(*Handler).CircleCallbackHandler(ctx context.Context, b *bot.Bot, update *models.Update)`. Новый PendingVideoStore хранит случайный непрозрачный token → ownerID, chatID, sourceMessageID, fileID, metadata hint, expiresAt, state, selectedMode. State: ready → awaiting_trim → processing → done; отказ до начала возвращает ready, отмена удаляет запись.

- [ ] Добавить тесты маршрутизации `Video` / видеодокумента / постороннего документа и подтверждение, что на этапе меню нет скачивания, ASR или списания. Metadata Telegram использовать как предварительную подсказку, после загрузки перепроверять Probe.
- [ ] Под видео создать две кнопки и «Отмена». Callback содержит только token и действие; общий размер ≤64 байт. Выбор длинного видео переводит меню в `awaiting_trim`, повторная отдельная кнопка подтверждает начало 0–60 секунд.
- [ ] Добавить mutex/CAS-переход в processing; проверить владельца, чат, срок жизни, допустимое действие и доступность сообщения. Быстро отвечать на callback. Чужой, повторный и просроченный callback не имеет побочных эффектов.
- [ ] Тесты: двойной click; разные видео одного пользователя; пользователь прислал новый файл до выбора старого; перезапуск/пустой store; TTL-cleanup; альбом; недоступное callback-сообщение. При занятых двух слотах не списывать и сохранить возможность повторить.
- [ ] Выполнить `go test -race ./internal/handlers`, зафиксировать коммитом.

## Задача 4. Оба режима и корректное завершение

**Интерфейс общего пути:** `(*Handler).processVideo(ctx context.Context, b *bot.Bot, job ProcessingRequest)`. `ProcessingRequest` содержит ownerID, chatID, sourceMessageID, fileID, sourceKind (`video`/`video_note`), mode (`plain`/`captions`), trimConfirmed. Тип объявить в `processing.go`; значения не брать напрямую из недоверенного callback.

- [ ] Добавить тесты: plain не вызывает Transcriber/ReserveNote; captions резервируется один раз по действующим настройкам; video_note по-прежнему сразу запускает captions. Минимальные интерфейсы зависимостей для тестов выделить у места использования.
- [ ] Общая последовательность: занять слот → скачать/Probe/проверить → при необходимости запросить подтверждение обрезки и завершить текущую попытку → резерв → ConvertToCircle → captions только по выбранному фрагменту → проверить итог → SendVideoNote → отметить delivered/логировать → cleanup. На стадии повторного подтверждения не держать слот или скачанный файл.
- [ ] Сохранить существующую функцию ASS. `AddSubtitlesToVideoNote` и извлечение аудио перевести на context-aware исполнение для общего таймаута. Не отправлять исходные десять минут в Whisper. Субтитры накладываются на нормализованный квадрат; аудио к этому моменту AAC.
- [ ] При отсутствии речи или звука вернуть резерв captions и предложить новый plain-job по сохранённому fileID. Не запускать бесплатную конвертацию автоматически. При успешном кружке и ошибке отдельного транскрипта плату не возвращать, как в текущем сценарии.
- [ ] Тесты с ошибкой на каждой стадии: возврат соответствующего резерва, освобождение слота, cleanup и терминальный статус. Повторный callback не запускает вторую отправку. Для timeout отправки не делать автоматический повтор; документировать возможный неоднозначный исход.
- [ ] Выполнить `go test -race ./internal/handlers ./internal/video ./internal/audio` и регрессию текущих пословных субтитров; зафиксировать коммитом.

## Оценка объёма и следующий этап

Ориентир для планирования: 2–4 рабочих дня на первую версию с интеграционными проверками и ручной приёмкой, при доступном тестовом боте/БД. Это оценка, не измеренный срок; HDR и изменения статистики могут увеличить объём.

После первой версии: кадр предпросмотра с выбором положения, затем выбор произвольного фрагмента. Переход к Mini App имеет смысл, если повторное использование и обращения пользователей подтвердят потребность в точном редактировании.
