# RU/EN landing, localization and attribution implementation plan

Goal: Ship the approved RU/EN landing, localized bot and /start source tracking on a temporary Dokploy address.
Architecture: existing Go bot/Postgres remains private; a separate Go HTTP service renders embedded HTML templates and static assets without bot secrets or database access. One repo and Compose deployment. RU/EN pages have independent metadata, reciprocal hreflang and same-language canonical. Temporary host is noindex until a permanent domain is configured.
Spec: user approval of docs/seo/2026-10-28/research-and-strategy.md, with implementation explicitly authorized without further design rounds.

## Task 1 — Attribution
- Add validated Telegram start parameter parsing, exact command routing incl @bot suffix, language hint from ru_/en_ prefix.
- Migrate User add Language, FirstSource, LastSource, FirstStartedAt; StartEvent history. Preserve user balances and original source under concurrent updates.
- DB interfaces: RecordStart(userID int64,source,language string) error; GetUserLanguage(userID int64)(string,error); SetUserLanguage(userID int64,language string) error; GetSourceStats()([]SourceStats,error). /start first no payload records direct.
- Package internal/attribution: Command(text string) string, ParseStart(text string)(source,language string,valid bool). Valid payload [A-Za-z0-9_-]{1,64}; invalid ignored, no arbitrary URL forwarding. Empty payload valid direct; hints ru_/en_.
- Tests: false command prefixes, bot suffix, malformed/overlong payload, concurrent first-touch, restarts and no balance reset; source stats meaningful without exposing IDs.

## Task 2 — Bot localization
- Own internal/handlers only, excluding attribution DB/main. RU/EN strings for onboarding/help, processing, errors, credits, invoices, admin stats. Locale persisted; Telegram language fallback; /language ru|en switch. Caption language remains original speech, not translation.
- StartHandler calls attribution.ParseStart, registers user, RecordStart then responds in selected language. /sources admin-only breakdown from GetSourceStats. Preserve payment amounts and logic.
- Tests: locale fallback, both locales, language persistence, exact /start handling with payload and nil updates. Keep helpers bounded, no new dependencies.

## Task 3 — Public landing
- Own cmd/landing and internal/landing only. stdlib Go server, embeds assets; separate Dockerfile.web root will be integrated by coordinator.
- Paths / (language chooser), /ru/, /en/, localized privacy/terms with accurate operational statements and no invented legal identity, /healthz, /robots.txt, /sitemap.xml. Return real 404. Temporary noindex configuration.
- Visual direction: warm ivory, dark ink, coral accent, editorial typography, large circular illustrated demo explicitly labeled illustrative. No fake users/testimonials/processing timers or claims about unimplemented formats. Animated word demo with reduced-motion fallback.
- Expose NewHandler(Config) http.Handler; Config fields BaseURL, BotUsername string; Indexable bool; FreeNotes, NoteCredits int; Packages [3]Package (Credits, PriceRub int). CTA deep links ru_home_hero/en_home_hero and footer equivalents. Never arbitrary UTM payload.
- RU/EN copy, FAQ, pricing uses actual supplied config; link parameters validated. Server rendered meta title/description, canonical/hreflang/OG; language switch preserves meaning. Tests HTML/head/status/robots/sitemap/escaping/bot links/localized prices.

## Task 4 — Integration, verification, deployment
- Coordinator sets public config from nonsecret production settings and resolves actual bot username without copying secrets. Add Dockerfile.web and web Compose service on dokploy-network, no public DB port. Expose internal 8080 via Dokploy generated HTTPS domain and Traefik.
- Run baseline and final go test -race, Postgres integration, FFmpeg test, go vet/build and Compose validation. Review combined diff, fix material findings with regression tests.
- Browser QA both languages on desktop/mobile, links/language switch/reduced-motion, temporary noindex. Deploy and inspect bot logs, DB migrations, no polling conflicts. Verify public response and source attribution via test only where no unsolicited messages are sent.
- Keep existing untracked research docs, avoid overwriting production secrets, report external services or end-to-end tests that remain unverified.
